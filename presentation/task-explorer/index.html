A Task Brief, inside a Task Explorer

A short explanation of a task, useful before a run and alongside a results story. Aim for a 60–90 second first read.

  1. Question + value. One concrete action and where it fits in a clinical or scientific workflow.
  2. What is given. Raw data, supplied helpers and callable tools shown separately. Mark reference-only material explicitly.
  3. Task contract. Required action, constraints, output shape and how success is checked.
  4. Visual explanation. Show input → assistance → output. Use native slices/overlays when available; label conceptual diagrams.
  5. What remains difficult. Explain the work left after assistance, backed by evidence when available.
  6. Sources + state. Pin the task/condition, distinguish drafts from published definitions, and state missing evidence.

Catalogue structure: capability or repository → task family → definition/revision → conditions and cases. Research ownership and supporting-study roles are separate axes. Repeated cases share a brief; every case should still be reachable.

Reuse: one repository rulebook and small template; a thin authoring skill follows them. Existing tours stay task-specific visual modules. No new general framework is needed.

The existing experiment protocol/scorer remains authoritative. A reader-facing brief is not automatically a runnable solver prompt. Rulebook, template and authoring skill implement the accepted convention. Source coverage remains explicitly scoped.
