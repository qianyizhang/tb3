# Comprehensive curation condition

[Instructions](instruction.md) · [Design and comparability](protocol.md).

One user-selected fresh Astra-medium condition reuses the case02 CT/runtime and
the broad context from the previous completed study. All-size plausible-candidate
curation and an oncologic-review purpose are explicit. `evaluate.py` wraps the
unchanged private scientific scorer with candidate-contract validation and a
predeclared >=0.5 probability subset for localization/segmentation only.

`prepare.py` refuses an existing `.local/longitudinal-ct-curation-v1` directory;
it requires the exact retained context-supplied freeze and its file manifest.
It does not download data, rebuild the solver or rerun historical author modules.
The private evaluator must be built from its prepared tests directory using the
verified runtime tag, pinned to its image digest, and checked with new native
oracle/no-op controls. `preflight.py` records the task-file manifest and exercises
the isolated CT-only solver image. `run_condition.py` requires a checked digest,
image identities and explicit current quota receipt, dispatches once, and captures
live isolation and model-transport evidence. Running it is a separately authorized
model action, never an inspection step.

After a terminal attempt, `audit.py` summarizes execution/trace isolation,
`analyze.py` independently replays saved outputs and renders native reference
comparisons, and `compare.py` compares the fixed scientific endpoints against the
two prior case02 conditions. `render_changes.py` renders the prior explicit
recognition disagreement and selected recovered/still-missed targets. Derived artifacts remain local. Do not regenerate
an existing analysis folder or historical freeze to change an outcome.

`trace_review.py` catalogs public actions and bounded generated-view geometry;
`trace_details.py` pins literal image requests and validates the final report's
explicit exclusion coordinates against source GT. Neither executes solver code
or converts a reference disagreement into a clinical adjudication.

`check_contract.py` runs a synthetic fixture with candidates on either side of
the probability threshold, verifies primary associations remain unchanged, and
checks that a missing sidecar fails only the expanded contract. It uses the
already installed medical Python runtime and does not launch a model.
