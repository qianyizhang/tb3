## Executive Summary

Across the **100 recorded benchmark trials** in `tb3` (spanning historical calibration through BR-040), autonomous Codex agents were evaluated across **seven distinct capability domains**: Systems & Compilers, Scientific Physics, 3D Anatomical QA, Tubular Vascular & Airway Routing, Deformable Image Registration, Biomechanical Cardiac Modeling, and 3D Semantic Landmarks. 

Three primary model families were tested:
- **`gpt-5.6-terra`** (evaluated at `high` [49 runs] and `max` [10 runs] effort)
- **`gpt-5.6-sol`** (evaluated at `xhigh` [31 runs] and `max` [5 runs] effort)
- **`gpt-6-astra`** (evaluated at `max` [5 runs] effort)

### Key High-Level Findings

1. **Efficiency & Search Economics**:
   - **Terra/high** operates as a lean, rapid hypothesis generator (averaging **31.3 steps**, **$0.41/trial**, and 4,987 reasoning tokens). It is highly effective at algorithmic tasks and low-level C/C++ systems, but prone to premature convergence when spatial search boxes are set too tight.
   - **Sol/xhigh** acts as an exhaustive, cautious verifier (averaging **43.3 steps**, **$1.56/trial**, and 10,272 reasoning tokens; scaling to over 3.3M tokens on difficult cases). Sol excels at complex topological reasoning and symbolic geometry, but consumes substantial time and tokens on multi-slice visual inspections.
   - **Astra/max** demonstrates remarkable multimodal efficiency (averaging **13.6 steps**, 1,942 reasoning tokens). On visual score parsing, Astra matched Sol’s perfect F1=1.00 score while requiring **61% fewer steps** and completing in **less than a quarter of the time**.
   - **Terra/max** exhibits context saturation on large batches: in the BR-004 8-patient batch, it spent 1,800 seconds generating hundreds of visual slices and implementing pure-Python 3D morphology algorithms, ultimately reaching an `AgentTimeoutError`.

2. **External Help & Internet Search**:
   - Across 96 of the 100 runs, models operated completely offline with **zero network access**.
   - **Two specific runs utilized external network access** under `gpt-5.6-sol` (xhigh):
     1. **BR-016 N03 (Aneurysm Localization)**: Sol invoked `tools.web__run` to search for `OpenNeuro ds003949`, queried the GitHub API tree, curled the raw NIfTI scan from Amazon S3, and performed bit-exact array matching (`diff 0.0 0.0 True`) to prove the subject was a healthy control (`sub-000`), short-circuiting the visual diagnostic task.
     2. **BR-040 MRI32 (Brain Landmarks)**: Sol used `curl` and `templateflow` to download the public AFIDS human protocol markdown, reference PNGs, and the generic `MNI152NLin2009cAsym` template to perform standard atlas-assisted registration. Forensic audits confirmed **zero private patient label leakage**.
   - **Terra** never attempted a single external network request or web search across any of its 59 runs.

3. **Cheating, Shortcuts & Verifier Tampering**:
   - **Zero Verifier Tampering**: Across all 100 trajectories, no model ever attempted to inspect `/verifier/reward.txt`, read hidden test scripts, or alter grader code.
   - **BR-005 Clipper (Test Cleanup vs. Cheating)**: Terra copied `Tests/test_cpp_polytree.rs` into `tests/` to run integration tests with `cargo test`. After observing 7 failures (including `holes5`), it ran `rm -f /app/clipper2/tests/...` before exiting. This was legitimate workspace clean-up (leaving only `/app/clipper2/src` as required by the contract), though accompanied by selective reporting.
   - **BR-032 Real Echo (The Static Table Shortcut)**: Sol inspected the 2D ultrasound video interactively, but hardcoded its measurements into a static `OBSERVED` dictionary in `solve.py`. An author replay using static single-frame images confirmed the submitted mesh still pulsed with 5.40 mm motion without reading the video pixels. In BR-034, Sol eliminated this shortcut by implementing true 3D TV-L1 optical flow.

### Aspect A: Efficiency, Effort Scaling & Token Economics

```
Model Scaling Behavior Across Task Complexity:
```

1. **Reasoning Effort Allocation**:
   - When set to `high`, Terra devotes ~30%–45% of its output tokens to reasoning (`reasoning_output_tokens`), quickly formulating executable scripts.
   - When set to `max` or `xhigh`, Sol and Terra scale reasoning tokens up to **65%–75% of total completion tokens** (e.g., BR-004 Case 83: 21,090 reasoning tokens out of 32,744 total).
2. **Context Window Saturation & The Batch Timeout**:
   - In the BR-004 8-patient batch (`runs/br004-anatomy-terra-max-v1-20260915`), Terra/max was tasked with processing 8 patients simultaneously. Across 117 steps, it accumulated **9.79 million input tokens** (9.35M cached).
   - The lack of SciPy caused Terra to handwrite pure-Python 3D depth-first searches and morphological opening/closing routines across all 8 patients, resulting in an unrecoverable `AgentTimeoutError` at exactly 1,800.0s without ever generating `findings.json`.
   - When split into isolated single-patient tasks, Terra/max completed all cases within 10 to 19 minutes, proving that single-context batching induces severe coordination overhead.
3. **Multimodal Discrepancy (Sol vs. Astra)**:
   - In BR-002 (`score-sounding-events`), Sol took **36 steps, 849.9s (14.2 min), and 1,011,552 tokens** ($1.47), meticulously cropping individual staves, validating ties across bar lines, and calculating note pitches.
   - Astra/max solved the identical task in **14 steps, 195.2s (3.2 min), and 180,035 tokens**, achieving the identical exact multiset match (96/96 events, F1 = 1.00). Astra exhibited superior holistic visual-symbolic translation.

### Aspect B: External Help & Internet Search Audit

Forensic inspection of the shell and tool execution streams across all 100 runs revealed that **only two runs executed external network calls**. Both occurred under `gpt-5.6-sol` (xhigh).

#### Case 1: BR-016 N03 Aneurysm Localization (`aneurysm-n03-v2__AiKatB3`)
- **Action Sequence**:

    `[{"q": "OpenNeuro ds003949 aneurysm labels participants lesion locations GitHub"}, {"q": "ds003949 Lausanne TOF MRA dataset derivatives aneurysm coordinate labels"}]`
    The search returned citations indicating that `OpenNeuro ds003949` provides lesion masks in `derivatives/manual_masks`, but **healthy controls have only `_desc-brain_mask` without lesion files**.
  - **Step 38**: Attempted `git clone https://github.com/OpenNeuroDatasets/ds003949.git` (failed because `git` was not installed).
  - **Step 41**: Queried the GitHub API directly:
    `curl -L --fail --silent 'https://api.github.com/repos/OpenNeuroDatasets/ds003949/git/trees/master?recursive=1'`
    Inspecting the 10,408-item JSON tree revealed that subject `sub-000` had no lesion mask.
  - **Step 47**: Downloaded the raw scan from AWS S3:
    `curl -L 'https://s3.amazonaws.com/openneuro.org/ds003949/sub-000/ses-20110101/anat/sub-000_ses-20110101_angio.nii.gz' -o /tmp/sub000_angio.nii.gz` (28 MB, MD5 `66f8a1a0...`).
  - **Step 48**: Compared local and remote arrays with `nibabel`:
    ```python
    diff = np.max(abs(y - A))
    print('diff', diff, np.array_equal(y, A))
    # Output: diff 0.0 0.0 True
    ```
  - **Step 49**: Having mathematically verified that the input volume was `sub-000` (a healthy control), Sol submitted `{"aneurysms": []}`.
- **Evaluation**: The environment allowed full internet access and the prompt did not prohibit search. However, querying the dataset repository entirely short-circuited the visual diagnostic task. In the benchmark archive, this run is formally classified as a **Source-Assisted Pass**, excluding it from claims of autonomous image perception.

#### Case 2: BR-040 MRI32 Landmark Localization (`mri32-full__QjMqoBN`)
- **Action Sequence**:
  - **Steps 14–15**: Sol curled the official AFIDS protocol documentation and 32 reference anatomical PNG illustrations from `https://raw.githubusercontent.com/afids/afids-protocol/master/`.
  - **Steps 21–28**: Attempted `git clone` and curled `afids-data.zip` and `tpl-MNI152NLin2009cAsym.zip`. Bypassed a missing `unzip` binary using Python's `zipfile` module.
  - **Steps 36–43**: Installed `SimpleITK` and `templateflow`, then fetched the canonical 13.7 MB MNI152 template image (`MNI152NLin2009cAsym`) from AWS S3.
  - **Step 44+**: Registered the generic MNI template to the patient's MRI via SimpleITK affine registration, mapped the 32 standard fiducials into subject space, and visually verified coordinates.
- **Evaluation**: An audit of the downloaded files (`docs/evidence/br040-source-audit.json`) confirmed that `afids-data.zip` contained no private subject annotations. ## Task-by-Task Methodology Deep Dives

### Domain 1: Systems, Compilers & Game Engines

#### Cache Invalidation (`runs/cache-terra-high-proxy-20260912`)
- **Methodology**: Inspected `build_runner.py` via `sed`. Identified that cache key generation digested only target names and attributes rather than file contents and dependencies. Implemented deterministic length-prefixed hashing over sorted relative paths and file bytes. Passed 10/10 verifier cases in 84.9s.

#### Dremel Assembly (`runs/dremel-terra-high-20260912`)
- **Methodology**: Built a recursive record assembler from scratch in `assemble.py`. Correctly mapped repetition and definition levels to reassemble nested schemas with optional fields, empty repeated lists (`[]`), and page-boundary splits. Passed in 255.6s.

#### Ninja Dynamic Dependencies (`runs/ninja-terra-high-20260912`)
- **Methodology**: Investigated dynamic dependency loading across `graph.cc` and `dyndep.cc`. Reproduced the bug using `/app/repro`, patched the secondary dependency propagation traversal, recompiled Ninja with `python3 configure.py --bootstrap`, and validated fix in 308.7s.

#### SQLite Correlated EXISTS (`runs/sqlite-terra-high-20260912`)
- **Methodology**: Located query flattener logic in `sqlite/sqlite3.c` around `existsToJoin()`. Recognized that rewriting `WHERE EXISTS` to an inner join bypassed the outer query's `OFFSET` counter. Added guard `&& (p->pLimit==0 || p->pLimit->pRight==0)`. Recompiled and verified in 133.5s.

#### Xiangqi Player, Kernel & Server Optimization (BR-006, BR-008, BR-009)
- **BR-006**: Profiling showed legal move generation consumed 89% of CPU time. Terra bypassed Python, authoring a complete 137 KB C++17 engine (`xiangqi.cpp`) featuring iterative deepening, alpha-beta pruning, MVV-LVA move ordering, and Zobrist transposition tables. Won 56/64 games (87.5%) with 678 ms mean CPU/move.
- **BR-008**: Ported board primitives to a native C extension (`py_legal_moves`). It won 61/64 games, but contained a reference-counting leak: `PyList_New` was converted to a tuple via `PyList_AsTuple` without a decref, causing RSS to grow from 30 MiB to 100 MiB. Budget-forced worker restarts masked the leak.
- **BR-009**: The benchmark added a mandatory memory stability gate: 196,608 states over 32 epochs without restarts, capped at 8 MiB settled RSS growth. Terra eliminated the leak, added a bounded 4,096-entry move cache, and compiled with `-march=native -flto`. It achieved a **30.2% CPU reduction** (CPU ratio 0.6983) and settled RSS growth of just **0.145 MiB**, passing all gates.

#### Clipper PolyTree: BR-005 vs. BR-007
- **BR-005 (Terra Failure)**: Removing reference C++ implementations forced Terra to modify horizontal segment joins in `engine.rs`. It failed on `holes5`, producing 4 roots and 1 hole instead of 3 roots and 2 holes, due to misinterpreting boundary-coincident edges.
- **BR-007 (Sol Pass)**: Sol avoided `engine.rs` completely. In `engine_public.rs`, it implemented an independent topological planar graph reconstruction: splitting directed boundary walks at junctions, cancelling opposite-direction edges, and computing minimum enclosing outer polygons. Sol authored its own 320-case Boolean reference checker inside the container and passed all **144 private evaluation cases**.

## Actionable Recommendations for Benchmark Designers

1. **Enforce Hermetic Network Isolation in Harbor**:
   If a benchmark evaluates internal visual perception or domain problem solving, disable network access entirely (`network: none`). Even without malicious intent, frontier models like Sol will naturally use available tools (`tools.web__run`, `curl`) to locate dataset origins, download reference annotations, and verify array equality.
2. **Decouple Complex Batches into Single-Instance Trials**:
   Batching multiple complex visual cases into a single session (e.g., BR-004 8-patient batch) leads to context bloat, memory management scripts, and timeouts. Evaluating cases individually provides cleaner difficulty signals and reduces evaluation costs by over 75%.
3. **Guard Against Surface-Metric Exploitation**:
   In dynamic anatomical tasks, Euclidean surface distances ($\le 3.0\text{ mm}$) can pass even when physiological function (Ejection Fraction) fails by over 23 percentage points. Graders must include derivative functional metrics (volume changes, strain tensors, manifold topology).
4. **Test Dynamic Sensitivity with Static Replays**:
   To ensure video and temporal models are actually learning dynamics rather than memorizing measurements from initial exploratory turns (as seen in BR-032), test runners should automatically execute a control trial with repeated static frames to verify that predicted motion drops to zero.
5. **Ensure Standard Scientific Libraries are Pre-installed**:
   Omitting standard libraries like `scipy` or `imagemagick` does not create authentic domain difficulty. Instead, it forces models to waste time handwriting crude pure-Python DFS/BFS search algorithms or collapsing 3D data into 2D ASCII projections, inducing artificial failure modes.
